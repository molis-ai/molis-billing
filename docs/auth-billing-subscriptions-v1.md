# Auth 订阅与 Billing 账本一期开发计划

**定稿日期：2026-11-25。状态：产品与技术规则已定稿，主体功能待开发。** 本文整合原联合执行计划、逐项评审结论与架构审校修订，作为本期开发与验收唯一依据。

用户在 Auth 登录后，可以为本人或所选团队购买 Work 测试套餐、主动续费、查看余额，为尚未生效的订单退款。支付走 Mock，订单、订阅及 Credit 流水真实写入 Billing D1。验收从 Auth 页面发起操作，以刷新后可见的结果和 Billing 账本为准。

## 2. 身份、账务归属与可见范围

每笔账归属于「产品 + 主体类型 + 主体 ID」。本人账与各团队账分别计算。个人空间只看个人套餐；团队空间只看当前团队套餐。团队的有效成员共享套餐权益，原有项目和数据权限继续适用。账本不跨个人、团队或产品混扣、垫付。

| 操作 | 本人 | 当前团队普通成员 | 当前团队所有者／管理员 |
| --- | --- | --- | --- |
| 看相应套餐、有效期、当前可用余额 | 本人账 | 团队账 | 团队账 |
| 看 Credit 用量 | 本人流水 | 仅自己在该团队发起的消费类流水（`HOLD`/`SETTLE`/`RELEASE`/`CONSUME`，服务端强制按 `actor_user_id` 过滤，不含同事记录及系统发放/失效/撤销明细） | 该团队全量明细 |
| 看订单金额和退款记录、购买、继续付款、续费、退可退订单 | 本人订单 | 无 | 团队订单，包括其他管理员（含已离队管理员）下的单 |

Billing 每次按可信身份复核操作和目标主体。租户停用期间暂停成员的团队业务操作（返回 `403 TENANT_DISABLED`），订阅日历和到期日继续计时；恢复后按原时间表判断，个人订阅照常。这里只定义 Work 套餐权益和账本能力，实际 Work 功能开关与计费接入属于后续工作。

## 3. Auth 页面上的购买、续费与退款

1. **选套餐**。页面明确显示购买主体名称、套餐、月付／年付、实际应付金额、每月到账额度。进入团队账单时始终显示当前团队名称，切换团队或退出账号时清掉上一个主体的结果，迟到响应不得覆盖新页面。
2. **创建订单**。Billing 生成「待付款」订单并冻结本次报价。付款截止时间为创建后 30 分钟。关页再回来可在订单列表点「继续付款」，沿用订单、价格和原截止时间。同一笔待付款订单的刷新、重试不重新计时。订单状态保持 4 态、不增设「已取消」：用户选错月付/年付可直接重下新单，原待付款订单 30 分钟后自然超时。
3. **确认模拟支付**。用户核对主体、金额和周期，点「确认模拟支付」。页面根据 Billing 确认的结果展示「支付成功」。只有支付成功才取得购买的服务期。到截止时仍未付款，显示「订单超时」（`409 ORDER_EXPIRED`），该订单不能再支付；用户重新下单按新报价确认。读写都校验截止点，清理任务延迟不能延长付款时间。两位管理员并发付款时，后到者命中「已有已付未来一期」直接原子拒付返回 `409 RENEWAL_ALREADY_PURCHASED`（不扣款，订单保持待付款直至超时）。
4. **看订阅和余额**。显示当前生效套餐、服务时间、已付至哪天、可用余额；有提前续费时另列下期起止和订单。金额、状态和余额均从 Billing 读取。读取失败显示可重试的加载错误，不能显示成余额为零或订阅已失效。
5. **直接退款**。对整笔服务期尚未开始的已付订单，先展示退款金额和对当前套餐的影响，确认后直接办理模拟退款，无人工审批。以服务端处理时刻判定，到了开始时刻即不可退（`409 ORDER_NOT_REFUNDABLE`）。生效后整单不可退，即使完全没用，年付还有多个月未发额度也一样。

| 订单状态 | 允许的结果 | 对业务的影响 |
| --- | --- | --- |
| 待付款 | 确认支付成功，或到期成为订单超时 | 此时不延长订阅、不发 Credit，也不占已付的提前续费名额；允许存在多笔待付款订单 |
| 订单超时 | 用户可重新下新单 | 原单保留供查询 |
| 支付成功 | 未生效时可申请整笔退款 | 持有订单对应的已购服务期 |
| 已退款 | 可查退款金额、时间及原订单 | 只撤回本单对应的服务期，重算已付至日期，其他订单照常 |

## 4. 服务期、月度额度与时间显示

| 情况 | 执行规则 |
| --- | --- |
| 首次购买、过期后重新购买 | 从实际支付成功时刻起算，当场发第一期额度。10:00 下单、10:20 支付成功，从 10:20 开始。过期后重买视作新周期，从新支付时间起算并按本次购买重置计费时区与日历锚点。 |
| 同款提前续费 | 支付成功时立刻更新已付至日期，新购买的服务期接在原到期时刻之后，**强制沿用原订阅的计费时区与日历锚点**。7 月 5 日续一个月、原到期 7 月 12 日，最终到期 **8 月 12 日**。下期额度 7 月 12 日到账。 |
| 可提前购买的数量 | 同一账户同一产品同时只有一个有效套餐，最多另有一笔已付且尚未开始的续费订单。可以预买一个月或一年。仅到期后可换另一档套餐；同一档月付与年付可在续费时互换，从下一期开始。 |
| 月付和年付 | 两者均按订阅月发放。年付一次购买十二个订阅月，每月按该订单版本发一次额度。上期未用额度在换期时失效，下期获得新额度。到期续购由用户主动确认。 |
| 定价和停售 | 拆分为套餐主表（`billing_plan.sale_status`：`ON_SALE` / `DISCONTINUED` + `current_version`）与只增快照表（`billing_plan_version`）。调价或改月额度时发布新版本并更新 `current_version`；新购与续费订单均采用当时在售最新版本，已付款及 30 分钟内待付款订单继续按原版本快照履约。整档置为 `DISCONTINUED` 后阻止新购与续费（`409 PLAN_DISCONTINUED`），已付订单包括未来一期照常兑现。 |
| 时间计算 | 下单可选传 `billingTimeZone`（前端默认传浏览器 `Intl.DateTimeFormat().resolvedOptions().timeZone`）；服务端校验为合法 IANA 时区名（非法返 `400 INVALID_TIMEZONE`），未传默认 `Asia/Shanghai`。以计费时区做月／年日历运算，保存 UTC 毫秒时间戳。1 月 31 日开通，2 月取月末，3 月回到 31 日；始终从原锚点推算。夏令时规则固定为：**缺失钟点（春跳）顺延至跳变后对应有效偏移，重复钟点（秋回）取第一次出现（早偏移）**。实现通过轻量 JS 运行时桥接复用 Cloudflare V8 原生 `Intl.DateTimeFormat`，零 WASM 体积膨胀且自带全量 IANA 时区库。 |
| 时间展示 | Auth 用查看者的当地时区显示日期和时间，并明确标示时区，如「2027-06-12 15:30（上海，UTC+08:00）」。切换查看者或设备不改变计费边界。 |

服务期使用左闭右开区间 `[开始, 结束)`。支付成功时间、每笔订单的服务期、整份订阅的已付至时间要分别保存或可确定地推导，所有接口共用同一日历计算与边界判定函数。

Auth 页面不再读取旧 Auth 商业接口来拼接新账务数据，统一经 Auth 同源 `/api/account/billing/*` BFF 代理至 Billing 下述用户侧接口：

| Billing 能力 | 接口与调用边界 |
| --- | --- |
| 看可售套餐、看当前和已购订阅 | `GET /api/v1/catalog/plans`、`GET /api/v1/subscriptions`；接受个人或所选团队上下文（由 Auth BFF 转发） |
| 查看、创建、继续支付订单 | `GET /api/v1/orders`、`GET /api/v1/orders/:id`、`POST /api/v1/orders`；购买和续费均经订单，继续支付复用原订单 |
| 模拟支付和退款 | `POST /api/v1/orders/:id/mock-pay`、`POST /api/v1/orders/:id/refund`；仅 Mock 适配器产生可信支付结果，服务端校验金额、币种、订单与主体 |

| 支付事件、平台审计、运行探针 | `POST /api/v1/webhooks/:provider` 独立验签并按事件去重；审计读取按权限分页。`health` 保持轻量，`readiness` 验证迁移所需的核心表确实可读。 |

### 统一业务错误码约定

| HTTP | 错误码 `error.code` | 触发场景 |
| ---: | --- | --- |
| `400` | `INVALID_REQUEST` / `INVALID_TIMEZONE` | 参数格式错误或非法 IANA 时区名 |
| `401` | `UNAUTHENTICATED` / `SESSION_EXPIRED` | 未登录或会话已失效/撤销 |
| `402` | `INSUFFICIENT_CREDITS` | 余额不足或新期无有效额度 |
| `403` | `FORBIDDEN` / `TENANT_DISABLED` | 越权操作（如普通成员下单/查他人流水）或目标团队已停用 |
| `404` | `NOT_FOUND` | 订单、套餐或主体不存在 |
| `409` | `ORDER_EXPIRED` | 超过 30 分钟支付截止时间 |
| `409` | `RENEWAL_ALREADY_PURCHASED` | 已有已付未来一期，并发续费拒付 |
| `409` | `ORDER_NOT_REFUNDABLE` | 订单已到服务期开始时刻或已非可退状态 |
| `409` | `PLAN_DISCONTINUED` | 套餐已停售，阻止新购与续费 |
| `409` | `IDEMPOTENCY_CONFLICT` / `VERSION_CONFLICT` | 同幂等键不同载荷，或并发写版本冲突 |
| `503` | `AUTH_UNAVAILABLE` / `BILLING_UNAVAILABLE` | 线上缺少 Service Binding 或下游鉴权/账务暂不可用 |

**Credit 跨期规则（分步独立落账）。** 有效期内发生的用量记在该期；换期时先结算旧期实际用量，未使用的旧预留到期失效，随后以新期额度承接后续用量。例：零点前实耗 4、零点后实耗 6，旧期扣 4、新期扣 6。**实现约束：跨期两段严禁强塞进同一个 D1 `batch`**——必须按期次顺序分别原子提交（先结清旧期 4，再尝试扣新期 6）；当新期无有效额度或余额不足时，返回 `402 INSUFFICIENT_CREDITS`，并在响应中明示 `settledSegments`（旧期 4 已落账可对账）与 `failedSegment`（新期 6 扣减失败），避免整批回滚吞掉旧期已发生的用量。任务暂停或隐式换账户均不属于该流程。测试使用可控时钟和分段用量，实际 Work 计量留至后续。

**时间驱动的账务（统一幂等同步）。** 发放唯一键至少覆盖 `(order_id, month_index)`。抽成单一幂等函数 `sync_credit_periods(owner, product, now)`，供支付、读余额、结算及定时任务共用，确保年付换月即使定时任务延迟也能立即返回正确余额：
- **旧月过期归档**：使用带版本 Guard 的原子批 `WHERE id=? AND version=? AND status='ACTIVE' AND expires_at<=?`，只有版本命中时才在同一 batch 写入一条 `EXPIRE` 流水，防止并发读余额写出重复 `EXPIRE` 流水。
- **新月额度发放**：依赖 `UNIQUE(order_id, month_index)` + Guard 保证最多插入一条月度额度与一条 `GRANT` 流水，遇到并发冲突自动重试读取一次。
- 定时清理按批次处理到期订单、超时预扣、到期月额度和过期幂等收据；重复或中断后重跑不能重复发放、释放或扣减。

## 6. 跨服务身份与一致性

- **Auth 同源 BFF 代理模式（零浏览器 Token、零 CORS）**：Auth 现有网页继续只使用 HttpOnly Cookie + CSRF 访问同源 `/api/account/billing/*`，**绝不向浏览器下发或暴露中央 Access Token 或独立前端凭证**。Auth BFF 验证当前浏览器会话与 CSRF 后，经 Cloudflare **Service Binding**（本地开发走 `127.0.0.1:8788` 回环）附带内部共享密钥与已验证身份转发请求到 Billing。退出、撤权、离队、换账号和跨租户访问都要有反例。
- **Auth 内网桥接**：沿用 `/internal/v1/sessions/introspect` 与 `/internal/v1/subjects/verify`，只返回本次操作所需字段，复用现有验票逻辑且**不刷新登录活跃时间**（`last_active_at`）。对本次鉴权使用的会话、客户端、成员、租户、产品及相关权限做一致性读取；Billing 在敏感写入及幂等回放前复核授权，并写明跨库鉴权与落账之间的保证边界。
- **内网通道与封闭失败**：线上环境（`test` / `prod`）Auth ↔ Billing 均通过对应环境的 Cloudflare **Service Binding** 直连并校验常量时间比对的 `X-Molis-Internal-Secret`；仅本地 `dev` 允许 `127.0.0.1` 回环地址。线上绑定或内部密钥缺失直接返回 `503` / `404` 封闭失败，确保公网无法访问任何 `/internal/v1/*` 入口。
- **原子与幂等**：金额和 Credit 写入均在服务端校验。账务写操作要求 `Idempotency-Key`，摘要包含操作、目标、主体和业务参数。业务变动、流水、审计和成功收据在同一 D1 原子批次提交。支付事件另以 `(provider, external_event_id)` 去重；同一 ID 内容不一致时拒绝处理。
- **提交点并发复核**：确认支付的提交点重新检查订单截止时间、主体、是否已有有效套餐或已付未来一期。两位管理员并发续费只能成功一次。支付和超时、退款和换期、结算和清理相撞时，以服务端时刻及原子条件决定结果。外部适配器副作用须有可重试的操作标识；Mock 的确认与回调返还相同履约结果。
- **生产剔除 Mock**：`PaymentProvider` 隔离支付实现。Mock 仅在允许的本地／测试环境启用，生产构建（`--no-default-features`）编译期剔除；实际部署入口与 dry-run 必须选中同一生产构建。内部密钥、访问凭证和回调密钥不进入日志、响应或 Git；账务 API 返回 `Cache-Control: no-store` 及基础安全响应头。

## 7. 开发顺序

| 顺序 | 交付物 | 通过条件 |
| --- | --- | --- |
| 1. 目录与身份 | 接续 `0002` 建 `billing_plan` 主表与后续迁移；完成 Auth `/internal/v1/*` 桥接与同源 `/api/account/billing/*` BFF 代理 | 同一浏览器无 Token 暴露即可读取本人与所选团队数据；普通成员的团队写入返回 `403` |

| 3. Credit 账本 | `sync_credit_periods` 幂等换月发币与过期归档、`/internal/v1/credits/*` 预扣／跨期分步结算／释放／直扣、普通成员流水隔离和对账 | 年付首月和跨月独立验证；并发读余额无重复流水；跨期新期不足时旧期实耗仍完整对账 |

| 5. 联调与回归 | 两仓测试、生产无 Mock 构建、真实登录的本地端到端 | 留下命令结果、关键订单与脱敏流水对账结果，区分已验与待验 |
